# ساخت نسخه قابل نصب متصل به سرور

این پروژه با Expo SDK 55 کار می‌کند. تنظیمات محیط سرور در پروفایل `release` فایل `eas.json` قرار دارد؛ پروفایل `apk` برای نصب مستقیم اندروید و `production` برای خروجی فروشگاهی است. HTTP در این پروفایل‌ها غیرفعال است.

نشانی‌ها:

- API: `https://api.aloogiyah.ir/api`
- فایل‌ها: `https://api.aloogiyah.ir`
- گفت‌وگو: `wss://api.aloogiyah.ir/ws/chat`

کد حراج و نگاشت وضعیت خدمات با دیتابیس نهایی سرور هماهنگ شده‌اند. این تنظیمات عمومی‌اند؛ رمز دیتابیس، کلید JWT و کلید امضای اپ نباید به متغیرهای `EXPO_PUBLIC_*` اضافه شوند.

## اندروید

دستورها را روی کامپیوتر، داخل همین پوشه اجرا کنید:

```powershell
npx eas-cli@latest login --browser
npx eas-cli@latest whoami
npx eas-cli@latest init
npm run build:apk
```

در مرحله init، پروژه باید در حساب خود مالک اپ ساخته یا انتخاب شود. اگر ابزار شناسه پروژه را در app.json ثبت نکرد، شناسه‌ای را که EAS نشان می‌دهد در `extra.eas.projectId` ثبت کنید؛ شناسه نمونه نسازید. تنظیمات پویا در app.config.ts سایر فیلدهای app.json از جمله extra را حفظ می‌کند.

برای امضای اندروید، در صورت نداشتن کلید قبلی می‌توان از تولید و نگهداری keystore توسط EAS استفاده کرد. برای به‌روزرسانی نصب‌های بعدی باید همان کلید امضا حفظ شود. اطلاعات ورود و کلید خصوصی را در چت نفرستید.

پس از پایان موفق ساخت، EAS لینک APK را نشان می‌دهد. آن را روی گوشی دانلود و نصب کنید. این نسخه مستقل از Expo Go و کامپیوتر اجرا می‌شود و برای داده‌ها به سرور نیاز دارد.

`npm run build:android` فقط بسته JavaScript/Hermes را بررسی می‌کند و فایل APK تولید نمی‌کند. `npm run build:apk` ساخت بومی APK را در EAS درخواست می‌کند.

### خطای آپلود 403 و پروکسی ویندوز

اگر پاسخ سرویس `storage.googleapis.com` عبارت `this service is not available in your location` داشت، مسیر اتصال آپلود محدود شده است. EAS CLI ممکن است تنظیم پروکسی ویندوز را خودکار استفاده نکند. با FlClash روشن، نشانی HTTP proxy واقعی برنامه را برای همان نشست PowerShell تنظیم کنید؛ برای تنظیم فعلی این کامپیوتر:

```powershell
$env:https_proxy = "http://127.0.0.1:7890"
npm run build:apk
```

پورت را با تنظیم FlClash تطبیق دهید. این متغیر فقط در همان PowerShell و برنامه‌های اجراشده از آن اثر دارد. این تشخیص مختص پاسخ محدودیت موقعیت است؛ هر خطای 403 الزاماً همین علت را ندارد.

## آیفون

خروجی بسته JavaScript برای iOS قابل بررسی است، ولی برای ساخت امضاشده آیفون با EAS و توزیع TestFlight، عضویت Apple Developer و اعتبارنامه امضا لازم است:

```powershell
npm run build:ipa
```

این دستور ساخت فروشگاهی را درخواست می‌کند؛ ارسال به App Store Connect/TestFlight مرحله جداگانه است. بدون حساب Apple Developer، از این مسیر IPA قابل نصب روی آیفون تهیه نمی‌شود. ساخت محلی توسعه روی آیفون با حساب شخصی Apple به Mac و Xcode نیاز دارد؛ روی ویندوز این مسیر موجود نیست. فایل شبیه‌ساز نیز روی آیفون نصب نمی‌شود.

## فایل‌های ارسالی

فایل `.easignore` در ریشه مخزن فقط پوشه موبایل را برای ارسال نگه می‌دارد؛ کد سرور، پشتیبان‌ها، فایل‌های محلی محیط، node_modules و اعتبارنامه‌ها ارسال نمی‌شوند. متغیرهای عمومی موردنیاز ساخت در eas.json آمده‌اند.
