# اپ موبایل الو گیاه

این پوشه یک پروژهٔ React Native با Expo SDK 55 و TypeScript است؛ کنار `frontend`، `backend` و `admin-panel` قرار می‌گیرد. رابط فارسی، فونت Vazirmatn و رنگ‌های سبز از زبان طراحی فرانت ارسالی گرفته شده‌اند. صفحه‌ها برای موبایل بازطراحی شده‌اند؛ این پروژه تبدیل خودکار یا نسخهٔ پیکسل‌به‌پیکسل HTML سایت نیست.

## نصب و اولین اجرا

Node.js نسخهٔ LTS سازگار با Expo 55 نصب باشد. برای اجرای محلی اندروید، Android Studio، SDK و یک شبیه‌ساز یا گوشی متصل لازم است.

ابتدا فایل‌های پوشهٔ `backend-mobile` کنار این پوشه را مطابق راهنمای پایین روی بک‌اند اعمال کنید. سپس در PowerShell:

```powershell
cd frontend-mobile
Copy-Item .env.example .env
npm ci
npx expo run:android
```

این دستور نسخهٔ توسعهٔ اپ را می‌سازد و نصب می‌کند. برای اجراهای بعدی:

```powershell
npx expo start --dev-client
```

برای iOS با ابزارهای محلی، macOS و Xcode لازم است:

```bash
npx expo run:ios
```

می‌توان از EAS Build برای ساخت ابری iOS روی ویندوز هم استفاده کرد. نصب روی آیفون و انتشار نیاز به تنظیم امضا و حساب مناسب Apple دارد. این بسته شامل APK یا IPA امضاشده نیست.

## آدرس سرور روی گوشی

در `.env`، سه آدرس را برای محیط خود تنظیم کنید:

```dotenv
EXPO_PUBLIC_API_URL=http://192.168.1.100:5056/api
EXPO_PUBLIC_MEDIA_URL=http://192.168.1.100:5056
EXPO_PUBLIC_CHAT_URL=ws://192.168.1.100:5056/ws/chat
EXPO_PUBLIC_ALLOW_HTTP=true
```

`192.168.1.100` نمونه است؛ IP کامپیوتر خود را از `ipconfig` بردارید. گوشی و کامپیوتر باید در یک شبکه باشند. در شبیه‌ساز Android Studio، `10.0.2.2` به کامپیوتر میزبان اشاره می‌کند. `localhost` روی گوشی به خود گوشی اشاره دارد.

برای دسترسی از گوشی، بک‌اند باید روی شبکه گوش بدهد. در پوشهٔ بک‌اند اجرا کنید:

```powershell
dotnet run --project AlooGiyah_Api --launch-profile http --urls "http://0.0.0.0:5056"
```

اجازهٔ اتصال پورت 5056 را برای شبکهٔ خصوصی در فایروال تنظیم کنید. آدرس سرور را ابتدا در مرورگر گوشی باز کنید. مسیر عمومی عکس‌ها باید URL قابل دریافت مانند `/Uploads/...` باشد؛ مسیر `C:\aloogiyah\Uploads\...` را گوشی نمی‌تواند باز کند.

پس از تغییر `.env`، Metro را دوباره اجرا کنید. تغییر تنظیم مجاز بودن HTTP به ساخت مجدد اپ نیاز دارد. برای محیط اصلی از HTTPS/WSS و `EXPO_PUBLIC_ALLOW_HTTP=false` استفاده کنید؛ پروفایل production نیز HTTP را غیرفعال می‌کند.

## دو فایل بک‌اند همراه بسته

ساختار `backend-mobile` با بک‌اند فعلی یکسان است:

1. فایل **جدید** `AlooGiyah_Api/Controllers/MobileCatalogController.cs` را اضافه کنید. این Controller سرویس‌های موجود را مصرف می‌کند و فهرست محصولات، مزارع، دسته‌ها و مزارع کاربر را با `items`، `totalCount`، `pageNumber` و `pageSize` برمی‌گرداند. پاسخ endpointهای قبلی سایت تغییر نمی‌کند.
2. فایل **کامل** `AlooGiyah_Persistence/Queries/AgriculturalProductQuery.cs` را جایگزین نسخهٔ فعلی کنید. تفاوت آن، اجرای مرتب‌سازی معتبر قیمت، موجودی و نام است. فیلد مرتب‌سازی از یک فهرست ثابت انتخاب می‌شود و متن کاربر وارد SQL نمی‌شود.

Migration جدید، تغییر JWT، تغییر RefreshToken یا تغییر Program.cs لازم نیست. DI همین سرویس‌ها در پروژهٔ ارسالی موجود است. پس از کپی فایل‌ها `dotnet build` را اجرا کنید. فایل‌های اصلی را پیش از جایگزینی نگه دارید.

## تنظیم وضعیت‌های واقعی

دو تنظیم مانند فرانت فعلی، باید با داده‌های واقعی محیط شما تکمیل شوند:

```dotenv
EXPO_PUBLIC_AUCTION_OPEN_STATUS_CODE=کد_واقعی_حراج_باز
EXPO_PUBLIC_SERVICE_STATUS_LABELS={"کد_واقعی":"عنوان وضعیت"}
```

تا قبل از تنظیم کد واقعی، ساخت حراج جدید غیرفعال است؛ مشاهده و پیشنهاد قیمت به حراج‌های موجود به API متصل است. کد وضعیت محصول قابل فروش `251BC4A57D` از فرانت فعلی گرفته شده و در فرم محصول قابل تغییر است.

## نقشه و فایل

نقشه در اپ بومی، Leaflet/OpenStreetMap داخل `react-native-webview` است؛ صفحهٔ کامل سایت داخل WebView قرار نگرفته است. کد Leaflet، CSS و آیکون‌هایش داخل بسته قرار دارند. دریافت کاشی‌ها به اینترنت نیاز دارد و برای استفادهٔ گسترده باید سرویس کاشی مناسب حجم کاربران انتخاب شود. کلید Google Maps لازم نیست.

روی نقشه برای انتخاب موقعیت بزنید یا اجازهٔ موقعیت مکانی بدهید. مجوز تصویر و موقعیت در تنظیمات Expo تعریف شده‌اند. توکن‌ها در HTML نقشه یا URL تصاویر قرار نمی‌گیرند.

## معماری

- `src/design-system/atoms`: متن، دکمه، فیلد، کارت و نشان وضعیت.
- `src/design-system/molecules`: انتخاب‌گر، کارت محصول و حالت دریافت داده.
- `src/design-system/organisms`: نقشه، انتخاب محصول، آدرس، بارگذاری و کنترل ورود.
- `src/design-system/templates`: قالب صفحه و مدیریت کیبورد و اسکرول.
- `src/screens`: ترکیب بخش‌ها و جریان هر صفحه.
- `src/api`: قراردادهای API، مدیریت نشست و کلاینت احراز هویت.
- `src/shared`: تایپ، فونت، رنگ، محاسبات نمایش و hookهای مشترک.
- `src/navigation`: مسیرهای دارای تایپ و تب‌های پایین.

React Query اطلاعات سرور را مدیریت می‌کند. برای این نسخه Store اضافی لازم نبود. SecureStore به جای کوکی مرورگر استفاده می‌شود. ورود توکن مهمان را همراه درخواست می‌فرستد تا بک‌اند سبد مهمان را ادغام کند. RefreshToken به شکل رشتهٔ JSON مطابق قرارداد فعلی ارسال می‌شود. درخواست‌های هم‌زمان یک تمدید مشترک دارند؛ درخواست متعلق به حساب قبلی پس از تغییر حساب دوباره اجرا نمی‌شود.

## ساخت خروجی

```powershell
npx eas-cli login
npx eas-cli build:configure
npx eas-cli build --platform android --profile preview
```

پروفایل `preview` برای Android خروجی APK می‌سازد. برای انتشار از پروفایل `production` استفاده کنید و URL سرور عمومی HTTPS را در محیط ساخت تنظیم کنید:

```powershell
npx eas-cli build --platform all --profile production
```

`npm run build:android` و `npm run build:ios` فقط بستهٔ JavaScript/Hermes را می‌سازند؛ این دستورها APK یا IPA تولید نمی‌کنند.

پیش‌نمایش اختیاری مرورگر با `npm run web` قابل اجرا است. ذخیرهٔ توکن در پیش‌نمایش وب فقط در حافظه است و با refresh صفحه پاک می‌شود. عکس‌برداری و آپلود اصلی برای Android/iOS نوشته شده است؛ پیش‌نمایش مرورگر جای تست اپ بومی را نمی‌گیرد.

## حدود اعتبارسنجی و محدودیت‌های موجود

- TypeScript و ۱۳ تست خودکار احراز هویت، قیمت‌گذاری و اسکریپت نقشه بررسی می‌شوند؛ تست‌ها از سرور HTTP محلی استفاده می‌کنند.
- بستهٔ JavaScript برای Android و iOS ساخته شده است؛ تست نصب روی گوشی، WebSocket واقعی، دسترسی فایل و موقعیت، و خرید روی دیتابیس شما انجام نشده است.
- بک‌اند تغییرات با امضاهای سرویس‌های ارسالی تطبیق داده شده؛ کامپایل .NET در این محیط انجام نشده است.
- بازبینی ظاهری روی شبیه‌ساز یا گوشی انجام نشده است؛ تنظیمات ریز ظاهر را پس از اولین اجرای واقعی بررسی کنید.
- سرویس `PaymentGatewayService` در بک‌اند ارسالی اتصال واقعی به درگاه ندارد؛ درخواست شارژ آنلاین پیام همین بک‌اند را نمایش می‌دهد. پرداخت سفارش با موجودی کیف پول از API موجود استفاده می‌کند.
- `RequestPhoneCodeAsync` در بک‌اند فعلی فقط در Development و با `Auth:PhoneOtpEnabled=true` کار می‌کند. برای دریافت کد آزمایشی، `Auth:ExposeOtpCodeInDevelopment=true` است. محیط اصلی به سرویس واقعی پیامک نیاز دارد؛ ورود و ثبت‌نام با رمز نیز در اپ وجود دارد.
- اعلان‌های داخل حساب پیاده شده‌اند؛ Push Notification هنگام بسته بودن اپ، به ثبت دستگاه و سرویس ارسال Push در بک‌اند نیاز دارد و در این بسته اضافه نشده است.
- تاریخ فرم‌های درخواست و حراج، فعلاً میلادی با الگوی مشخص ورودی است؛ تاریخ‌های نمایشی فارسی هستند.

فرمان‌های بررسی:

```powershell
npm run typecheck
npx expo install --check
npm run build:android
npm run build:ios
```
