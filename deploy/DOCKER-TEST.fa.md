# گزارش تکمیلی آزمون Docker — ۳۱ اکتبر ۲۰۲۶

## تأیید شده
- ساخت سه image تولیدی وب، API و پنل و اجرای چهار سرویس Compose.
- اجرای ۴۱ migration روی دیتابیس جداگانه آزمایشی.
- سلامت API و پس از افزودن fixture نقش User و هفت وضعیت سفارش، آمادگی API هر دو 200.
- ثبت‌نام معتبر و رد ثبت‌نام ناقص و تکراری؛ ورود معتبر و رد رمز اشتباه.
- تمدید توکن و رد استفاده مجدد refresh token.
- تغییر رمز؛ رد توکن قبلی و رمز قبلی؛ پذیرش رمز جدید.
- پروفایل، کیف پول، قابلیت‌های کیف پول، سبد خالی، خلاصه و تعرفه و فهرست تسویه: 200.
- رد دسترسی بدون توکن: مدیریت، پروفایل، کیف پول، سبد و فایل‌ها.
- رد توکن نامعتبر و دسترسی مهمان به مدیریت و کیف پول؛ پذیرش مهمان برای فهرست محصولات.
- ورود مدیر آزمایشی و Dashboard، Lookups، Audit، Manage تسویه و فهرست کاربران: 200.
- CORS دامنه مجاز را پذیرفت و برای دامنه غیرمجاز هدر دسترسی صادر نکرد.
- محدودیت ورود پس از درخواست‌های پیاپی 429 صادر کرد؛ Swagger در Production برابر 404.
- ۱۵ مسیر وب از جمله خانه، ورود، ثبت‌نام، محصول، دسته‌بندی، مزرعه، مقاله، قوانین و مسیرهای داشبورد: HTTP 200.
- پنل و مسیر fallback آن: HTTP 200.
- ارتباط داخلی وب به API با DNS شبکه Docker: 200.
- نوشتن با کاربر غیر root در سه volume فایل؛ باقی ماندن فایل بعد از restart؛ باقی ماندن حساب و امکان ورود پس از restart دیتابیس.
- lint وب: صفر خطا و هفت هشدار بهینه‌سازی تصاویر.

## ایراد اصلاح‌شده
ایجاد و حذف اسلایدر کنترل نقش نداشت. هر دو اکنون فقط برای Admin و Manager مجازند. API بازسازی و کانتینر جایگزین شد؛ هر دو عملیات برای ناشناس 401 و برای مهمان 403 دادند.

## حدود آزمون و کارهای باقی‌مانده
- پاسخ HTTP صفحات به معنی تأیید ظاهر، JavaScript مرورگر و تمام تعاملات نیست؛ آزمون بصری مرورگر انجام نشد.
- داده پایه اضافه‌شده fixture تست است؛ seed کامل و آماده استفاده تجاری نیست. برای انتشار، دیتابیس و فایل‌های واقعی باید منتقل شوند.
- خرید دارای موجودی، هم‌زمانی مالی، بازپرداخت، مزایده، مالکیت چند فروشنده، آپلود محتوای واقعی و گردش کامل سفارش در این نوبت تأیید نشدند.
- پرداخت بانکی، پیامک، ایمیل واقعی، HTTPS دامنه‌های واقعی و بازیابی کامل پشتیبان تست نشدند.
- اپ موبایل در این آزمون Docker بررسی نشد.
- یک هشدار کتابخانه اختیاری Kerberos در اتصال PostgreSQL مشاهده شد؛ اتصال با رمز و migration موفق بود.
- سرویس‌های آزمایشی روشن‌اند. وب: 13001، پنل: 4173، API: 5056. حساب‌های آزمایشی و رمزهای این محیط برای انتشار مناسب نیستند.

نتیجه: ساخت، اجرای کانتینرها و جریان‌های فهرست‌شده تأیید شده‌اند؛ این گزارش تأیید همه قابلیت‌های محصول یا مجوز انتشار عمومی نیست.

## تکمیل آزمون بدون درگاه و پیامک
- حساب‌های A، B و C صرفاً آزمایشی ایجاد شدند. گردش خرید با محصول ۱۰٬۰۰۰ تومانی و موجودی ۱۰ اجرا شد.
- دو واحد محصول: سبد و Checkout برابر ۲۰٬۰۰۰؛ موجودی پس از رزرو ۸.
- تکرار درخواست ایجاد Checkout همان خرید را برگرداند. پرداخت با کیف پول خالی رد شد.
- اعتبار ۱۰۰٬۰۰۰ فقط با fixture دیتابیس تست ایجاد شد؛ هیچ شارژ بانکی انجام نشد.
- پرداخت کیف پول و تکرار آن: فقط یک HOLD برابر ۲۰٬۰۰۰. بررسی مستقیم جدول تراکنش، یک رکورد برای هر مرجع نشان داد.
- رد سفارش توسط خریدار 403 و حساب ثالث 404؛ رد توسط مالک مزرعه 200. وجه رزرو آزاد و موجودی از ۸ به ۱۰ برگشت.
- خرید دوم، تأیید فروشنده و کسر وجه موفق؛ تأیید تکراری 403. مانده ۸۰٬۰۰۰ و heldAmount صفر. یک رکورد CAPTURE ثبت شد.
- درخواست خرید ۱۰۰ واحد با موجودی ۸: پاسخ 409؛ موجودی نهایی همچنان ۸.
- سفارش دوم: ارسال فروشنده، دریافت میدان، ایجاد محموله با نماینده مدیر آزمایشی، صدور کد برای خریدار و تأیید توسط نماینده موفق؛ وضعیت نهایی Completed. کد نامعتبر 400 و تأیید توسط خریدار 403؛ تکرار تأیید نماینده بدون ثبت تحویل دوباره موفق بود. این کد در API حساب خریدار صادر می‌شود و ارسال پیامکی تست نشد.
- قابلیت درگاه و تسویه خودکار false؛ شارژ آنلاین و مبلغ منفی رد شدند؛ callback جعلی تأیید نشد (404). موجودی پس از تلاش‌های شارژ صفر باقی ماند.
- گفت‌وگوی دو حساب و ارسال متن موفق؛ حساب ثالث خواندن گفتگو 404 و ارسال متن 403؛ متن خالی 400.
- PNG معتبر در گفت‌وگو پذیرفته شد. PNG با محتوای جعلی و EXE رد شدند. دانلود فایل برای دو شرکت‌کننده 200 و برای حساب ثالث 403.
- مرورگر: خانه با داده نمونه، فرم ورود، ورود واقعی حساب ساختگی، داشبورد و پیام غیرفعال‌بودن شارژ در کیف پول بررسی شدند؛ در لاگ‌های مشاهده‌شده خطای console وجود نداشت. آزمون تمام صفحات، اندازه‌های نمایش و مرورگرها انجام نشد.
- TypeScript و lint اپ موبایل موفق؛ اجرا روی گوشی یا BlueStacks انجام نشد.

## اصلاح دوم
درخواست کد تأیید ایمیل برای کاربر بدون ایمیل قبلاً 500 می‌داد. اکنون پیش از ساخت کد، وجود ایمیل و تنظیمات SMTP بررسی می‌شود و پاسخ 400 با پیام روشن برمی‌گردد. هر دو حالت نبود ایمیل و نبود SMTP داخل کانتینر تست شدند؛ هیچ ایمیل واقعی ارسال نشد.

ساخت مجدد Docker برای این اصلاح به علت timeout و اختلال DNS در api.nuget.org متوقف شد. publish محلی با بسته‌های موجود موفق بود و DLL اصلاح‌شده فقط برای تست به کانتینر آزمایشی کپی و سرویس restart شد. بنابراین image ذخیره‌شده قبلی شامل این اصلاح نیست و روی سرور باید از سورس بسته جدید build انجام شود؛ بازسازی کانتینر فعلی نیز اصلاح runtime را برمی‌گرداند مگر ابتدا image بازسازی شود.

## موارد همچنان تأییدنشده
اتصال بانکی و پیامکی واقعی، ارسال SMTP واقعی، رقابت هم‌زمان چند خریدار، تست بار، همه حالت‌های تخفیف و مزایده، همه مسیرهای تسویه و اختلاف، بررسی جامع امنیتی، HTTPS واقعی و اجرای اپ روی گوشی. داده و اعتبار آزمایشی جایگزین انتقال دیتابیس واقعی نیستند.
