# نقشه و جست‌وجوی مکان

نقشه وب و موبایل از GET /api/Map/Config تنظیمات می‌گیرد. انتخاب شهر به زوم خودکار
منجر می‌شود؛ جست‌وجوی خیابان فقط با دکمه یا Enter انجام می‌شود.
نتیجه جست‌وجو نقشه را جابه‌جا می‌کند؛ کاربر باید نقطه دقیق را انتخاب کند.
نام افراد، شماره تماس و نشانی خصوصی نباید به جست‌وجوی مکان ارسال شوند.

## راه‌اندازی

مهاجرت 20261018180000_MapSearchCache باید پیش از سرویس‌دهی نسخه جدید اعمال شود.
مسیر موجود برنامه برای مهاجرت، اجرای API با آرگومان --migrate و تنظیمات همان محیط است.
دو جدول مستقل برای کش و نوبت ساخته می‌شود؛ داده‌های موجود تغییر نمی‌کنند.

تنظیمات محیطی API:

- Maps__SearchEnabled: غیرفعال کردن جست‌وجو بدون انتشار دوباره موبایل.
- Maps__SearchUrl: سرویس HTTPS سازگار با پاسخ Nominatim.
- Maps__UserAgent: هویت ثابت برنامه؛ پیش‌فرض Aloogiyah-App/1.0. اطلاعات تماس واقعی را می‌توان افزود.
- Maps__TileUrl: نشانی HTTPS تصاویر نقشه؛ پیش‌فرض نشانی استاندارد OSM.
- Maps__Attribution: نام و لینک مجوز؛ هنگام تغییر ارائه‌دهنده به‌روزرسانی شود.
- Maps__MaxZoom: بیشترین بزرگ‌نمایی؛ حداکثر ۱۹.

همه نمونه‌های API باید به یک پایگاه داده متصل باشند. قفل PostgreSQL و جدول نوبت
برای همه کاربران مشترک‌اند. نتایج هفت روز کش می‌شوند و فاصله بعد از هر پاسخ حداقل
۱٫۱ ثانیه است. خطاها خودکار تکرار نمی‌شوند. پاسخ ۴۲۹ وقفه حداقل یک دقیقه و
۴۰۳ وقفه سی دقیقه ایجاد می‌کند. انتظار در صف پس از ۲۰ ثانیه لغو می‌شود.
تصاویر نقشه از کش استاندارد مرورگر/WebView استفاده می‌کنند؛ کش جست‌وجو جداست.

## آزمون

آزمون سرور با PostgreSQL موقت و سرویس ساختگی انجام می‌شود:

    dotnet build backend/tests/MapSearch/MapSearch.csproj -o .tmp/map-tests-build -m:1
    node --test backend/tests/map-search.test.cjs

هیچ داده واقعی یا درخواست آزمایشی به Nominatim ارسال نمی‌شود.
شاخص‌های Meter با نام Aloogiyah.Maps:
map.search.cache_hits، map.search.upstream_requests،
map.search.upstream_errors و map.search.queue_seconds.
متن جست‌وجو در این شاخص‌ها ثبت نمی‌شود.

## ظرفیت

OSM سقف تضمین‌شده تعداد کاربر یا نمایش نقشه اعلام نکرده است.
سرویس عمومی جست‌وجو سقف یک درخواست در ثانیه برای کل برنامه دارد؛
این سقف ظرفیت تضمین‌شده نیست. با زمان پاسخ سرویس، ظرفیت عملی کمتر است.

مثال: ۱۰۰۰ کاربر فعال روزانه، با فرض اینکه ۲۰٪ یک جست‌وجوی بدون کش انجام دهند،
حدود ۲۰۰ درخواست روزانه ایجاد می‌کند. اگر هم‌زمان جست‌وجو کنند صف تشکیل می‌شود.
تعداد حساب‌های ثبت‌شده معیار مصرف نیست.

آستانه پیشنهادی داخلی، نه محدودیت رسمی: در ۱۵ تا ۲۰ جست‌وجوی بدون کش در دقیقه
به‌صورت پیوسته، انتظار معمول بیش از ۳ تا ۵ ثانیه، یا خطای محدودیت/مسدودی،
ارائه‌دهنده دارای ظرفیت قراردادی بررسی شود.
برای تصاویر نقشه، مصرف و نیاز به پایداری مهم‌اند؛ سقف کاربران روزانه تضمین نشده است.
